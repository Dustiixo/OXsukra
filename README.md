# ECHOFOLD Ocean G0.1 — native, six-degree-of-freedom IXO navigation

**Status: isolated local proof, 17 November 2026.** A native Godot 4.6 desktop scene plus a read-only Python exporter that takes actual IXO Convergence G0.4 project/entry IDs, recorded state, approved links, exact source hashes and a journal-head identity into a navigable 3D ocean. The packaged starting snapshot was generated by the **real G0.4 engine** in a disposable test data store (2 projects, 5 entries, 9 verified journal events). It is synthetic *content*, not the owner's actual ASUS project history.

This does **not** modify your existing `%USERPROFILE%\IXO-work`, integrate the unverified authoritative Spine branch, connect to hardware, create a web application, or grant any AI execution authority.

## Quick start: explore the included real-G0.4 demo snapshot

1. Install/open the native Godot **4.6.x** editor (or use another compatible Godot 4.x after testing).
2. Import the file `godot/project.godot` as a new project, then press **F5** to play the project.
3. On Windows, `START_OCEAN_WINDOWS.cmd` also launches directly if the `godot` command is on PATH. On Linux, run `./start_ocean_linux.sh`.
4. Click/focus the Ocean window. Keyboard controls work immediately. If an Xbox 360 controller is connected, press **Start** to arm it; Start again returns to standby.
5. Aim at a sphere, press **A** (or **F**). For an entry, its true G0.4 source identity, stored next step, and original excerpt (demo only) appear. Press **B** (or **Backspace**) to return to the exact camera transform.
6. Press **X** to show source-approved links, **Y** for God's Eye View; B returns to the previous pose. Close and relaunch to test breadcrumbs.

### Actual input mapping

| Xbox 360 input | Keyboard fallback | Function |
|---|---|---|
| Left stick | W/A/S/D | Translate forward/back/strafe |
| Right stick | Arrow keys / right-mouse drag | Look yaw/pitch (no forced horizon) |
| RT / LT | E / Q | Ascend/descend relative to swimmer |
| RB / LB | C / Z | Roll freely |
| A | F / Enter | Enter targeted object |
| B | Backspace / Escape | Unwind one exact breadcrumb |
| X | X | Sonar: reveal approved relationships |
| Y | G | God's Eye View, with saved return pose |
| Start | Tab | Arm/release controller inputs |

This maps six degrees of freedom: forward/back, left/right, up/down, yaw, pitch and roll. Movement uses acceleration/damping. Controller inputs are ignored when unarmed or when the Ocean window is unfocused. On Godot 4.6, the adapter applies an explicit window-focus guard because gamepads may be delivered to unfocused applications. **This is not exclusive hardware ownership:** Steam/Epic/games may also read the same device if simultaneously active. Test on the intended ASUS before using Ocean alongside a game.

## Switch to your own real G0.4 records, safely

The included demo snapshot is only a disposable read projection. For your own data, first make a verified backup and confirm the source folder is in fact **G0.4**. Then export into a different directory, for example the `godot/data` directory in an extracted copy:

```powershell
py -3 bridge\export_ixo_snapshot.py --ixo-data "$env:USERPROFILE\IXO-Convergence-Data" --output "godot\data\ocean_snapshot.json" --replace-projection
```

The Python exporter opens both IXO databases **read-only**, verifies IXO's hash-linked journal, verifies each selected source against the Workbench metadata and original SHA-256 blob, then writes only the requested separate JSON projection. It refuses output paths inside the authoritative IXO data folder. The default projection does **not** include original text bodies. To intentionally display private source snippets in Ocean, add `--include-excerpts` after reviewing the privacy implications.

The Godot project loads `godot/data/ocean_snapshot.json`. To load an alternate projection file without replacing the demo, launch:

```sh
godot --path godot -- --ocean-snapshot=/absolute/path/to/projection.json
```

The projection is a **read model**, not a writable parallel database. Changes made in IXO will **not** appear until you export a fresh snapshot and reload Ocean. We do not claim live event subscription or exact cross-program readback. Original source hashes remain visible for reconciliation.

## Geometry and memory

- Project anchors are reproducibly placed in 3D from their stable project IDs.
- Entry nodes occupy a small local cloud around their parent project; labels use original titles.
- Green spheres mark project anchors, blue mark ordinary records, red mark blocked records.
- Tethers join entry to project; sonar reveals only human-approved IXO links.
- A breadcrumb stores camera position **and full orientation basis** before entering a node or switching to overview. B returns to that transform.
- A bounded stack (maximum 50) and last pose are saved separately under Godot's own `user://` storage, keyed to the snapshot state identity. They are not presented as the complete separate Opris memory-card engine.

## Tests and limitations

Run independently:

```sh
python3 -m unittest discover -s tests -q
godot --headless --path godot --script res://tests/ocean_smoke.gd
```

Godot's test verifies **actual scene instantiation** and the native record selection/breadcrumb path against the included verified G0.4 snapshot. Tests do not demonstrate a physical Xbox 360 controller, a Windows graphics-driver launch, actual live system focus arbitration, or native IXO deep linking into its existing Tk UI. Those are the next host verification gates.

The Godot read-only details view is a native projection of a source-backed record; it does not call `IXO.progress` or open/execute external applications. Live privileged adapters remain blocked pending the separate R11RF6 protected-broker repairs.
