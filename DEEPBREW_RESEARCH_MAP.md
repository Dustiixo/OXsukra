# The DeepBrew Research Map

## The thesis

A playable recording can be the entrance into a *persistent, manipulable object* that has multiple honest representations: what was recorded, what is measured, what the human intended, what a model proposed, what changed, and what the system learned from correction. A perspective is not a different copy of the truth.

## The four lenses

**Water's Edge:** the audible interaction and point of impact: the boundary at which an accepted change enters the ongoing music. Align modifications at musically meaningful times, not an arbitrary 30-second timeout.

**Black Hole:** convergence: trace sources, response objects, intentions, and dependencies back toward an anchor. The center is an identity/relationship focus, not an implication that all data has a common format.

**DeepBrew Object:** expand the one source into a rotatable measured spectro-temporal sculpture. Select a feature, pin an observation, create a non-destructive slice, and maintain the content address of the original.

**Thought Spine:** step outside the immediate sound. Compare the source, transformations, proposals, rejected branches, corrections and provenance across time. The system should tell you exactly which claims are raw facts and which are judgments.

## What would make it bigger (but still testable)

- M2 (this build): one normalized audio object + persistent original bytes, measured 3D projection, human approved local proposal, real audio response and revision, `.fid` save/reopen.
- M2.1: real timing/perceptual calibration. Quantify latency, onset alignment, pitch accuracy, pattern similarity, spectral transition smoothness, false onset rates. Test imported beatboxes, vocals, drum loops, full tracks, not only demo waveforms.
- M3: continuous zoom from one waveform to slices and from slices to source relationships. Distinguish 3D visualization state from actual sound edits. Add spectral selector as *an annotation first*, then optional offline filter preview with explicit undo.
- M4: independent memory/analysis process under a typed, versioned read-only interface. Compare local rule adapter and independently pinned Syntra adapter on the same exported evidence, without sharing unreviewed private memory.
- M5: more media object classes through adapters (code, image, drawing, motion, music). Each retains its native file format and domain semantics. ECHOFOLD may render the resulting graph, while Opris/Thought Spine preserve lineage.
- M6: richer VELA musical conversation (audio-conditioned generation, stem-aware variations, harmony/timbre alignment, adaptive response cadence) with model-independent benchmarks. Don't claim learning until saved feedback demonstrably changes later predictions.

## Why this combination matters

Self asks: *What if the thing you manipulate is the living object, not a separate form hiding behind it?* VELA asks: *What if that object is musical?* Syntra asks: *What if a cognition system can inspect the relationships and propose purposeful actions?* The governed Thought Spine answers: *What happened, who decided, what is supported, and can we undo it?*

The hard unsolved problem isn't drawing an MP3 as a sculpture. It's ensuring that operations across hearing, visual structure, memory, and planning are **semantically consistent, reversible, and independently verifiable**.

## Promotion rule

No proposal becomes a foundation module because it is conceptually attractive. A test demonstrates value, records inputs and outputs, survives replay on real devices, and only then is it eligible for promotion to IXO. Keep Alex's Syntra repository independent and only consume documented interfaces.
