# IXO — next engineering gates after the first two months
**Status:** forward work plan. No task here is represented as completed simply because it is documented.

## Gate 0 — recover the authoritative runtime and source
- Locate and hash the user-owned IXO-Multi-Program-Spine-v0.2 checkpoint, original branch/commit and its recorded Windows test/Proofbook receipt.
- Reconcile it against other staging/rebuild worktrees without flattening history.
- Run a secret/privacy/license scan before even considering public publication.
- Preserve existing package identities and databases; do not silently move or delete anything.
**Accept:** owner-visible manifest, independent file SHA-256 samples, exact host/environment, repeatable tests and clear provenance.

## Gate 1 — prove one real source-to-visual read-only path
- Select one real project node and its exact source record.
- Show same node in native IXO CLEAN, HUD, L33T and PROOF views.
- Carry the source reference through Thought Spine read-only, with optional DÉJÀ advisory cases.
- Distinguish measured signals, cached illustrations and planned links.
**Accept:** lossless canonical identity, correct no-source/offline states, accessibility, no source mutation and local restart persistence.

## Gate 2 — guarded candidate editing
- Require explicit human approval for exact source/scope, create isolated candidate and reproducible diff.
- Execute only via an owned adapter. Record environment/version and evidence before claiming success.
- Verify output with separate tests and OX WITNESS/Proofbook receipt checks.
- Demonstrate undo/rollback and no cross-owner state corruption.
**Accept:** one real end-to-end effect with independent before/after evidence and rollback.

## Gate 3 — two-owner transport
- One durable, typed and consented handoff between two existing owners. Never treat dispatch as permission.
- Recheck scope digest, permissions and expiry at receiving owner.
- Survive restart/queue replay, duplicate delivery and temporary disconnection.
**Accept:** reproducible signed or independently trusted receipts, replay denial, successful recovery.

## Gate 4 — packaging and multi-device acceptance
- Windows launch/close/restart/upgrade/rollback on target device.
- Linux native installation and audio/MIDI service boundaries where relevant.
- Android GREMLIN/TimePair lifecycle and offline queue reconciliation only after dedicated tests.
- Publish only approved, license-cleared and privacy-screened artifacts.
**Accept:** exact version, hardware/OS profile, automated logs, manual UI proof, rollback and known limitations.

## Immediate bounded next action
Do Gate 0 and only the first thin read-only piece of Gate 1. Every broader integration depends on verified original source identity, not reconstructed guesses or cinematic renders.
