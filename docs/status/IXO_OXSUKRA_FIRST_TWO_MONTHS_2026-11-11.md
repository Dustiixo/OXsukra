# OXsukra / IXO — The first two months
**Period:** approximately 10 September–11 November 2026
**Status:** evidence-aware historical consolidation; not a full installed-system certification.
**Scope:** architecture, owned programs, source packages, recorded tests, visual concepts and release gaps.

## Executive statement
We are building OXsukra, a local-first ecosystem of independently owned programs and adapters. IXO (pronounced Ico, “I coexist with my computer”) is the native operational workbench inside that ecosystem. The point is to make computing legible, inspectable, creative and user-governed: source files, code, models, music, memories and workflows retain real identities, owners, provenance, permissions and rollback paths.

This is NOT one monolithic program, a new OS kernel, a claim that every interface is already implemented, or a proposal to replace each existing subsystem with a browser dashboard.

The architectural principle is **convergence, not reinvention**. Preserve original source histories and independently owned stores. Build one authentic, bounded, verified integration slice at a time.

## What evolved during the period
### September into October: identity, memory and native foundations
- Defined the relationship: OXsukra is the umbrella; IXO is the native working environment.
- Developed the source and project-control model: local-first source intake, project graph, explicit approval before effects, versioned records, provenance and artifact evidence.
- Developed WRAP and Thought Spine for continuity, decisions, causal timelines, branching projects and source-linked history.
- Organized software ownership so agents/models advise while deterministic controllers retain time, execution, policy and release authority.
- Developed Foundry/Packbot-style source-preserving build and verification workflows rather than a synthetic master repository.

### Mid-to-late October: bounded components and the engineering discipline
- Consolidated source inventories, architecture atlases and component families; repeatedly separated historical references from installed code.
- Developed independent governance, research, evidence, orchestration and native workbench concepts and prototypes.
- Explicitly preferred Windows and Linux native workloads, local models for routine tasks, replaceable remote models for complex planning, and real adapters instead of pretend controls.
- Established Proofbook/OX WITNESS/Release Controller boundaries: proposed change → bounded execution → independent checks → human promotion or rollback.
- Kept cross-owner interfaces typed and reversible instead of merging unrelated SQLite databases or software histories.

### Early November: real host checkpoint, experimental loops and spatial language
- On 2 November, a **recorded Windows IXO checkpoint** used IXO-Multi-Program-Spine-v0.2, branch spine/v0.2, commit 14a29cd. Reported demonstrations included native navigation (HOME/SOURCE/DOOR/Project World), saved thoughts, evidence links, Proofbook receipt and a manual IXO-to-Goose-to-IXO handoff.
- Recorded receipt run-20261102T073515Z-969966ef747b: **66 passing tests plus 20 passing subtests, exit 0** for that scoped checkpoint. These figures are not universal OXsukra acceptance.
- A separate 3 November candidate bench reported **11 pass and 8 failed/blocked cases** among 19 cases, with two M² cases passing. It was not a unified installed acceptance run.
- Expanded EUREKA × DÉJÀ × CodeBot: hypothesize, retrieve earlier attempts as *advisory* evidence, test, compare, record and roll back. Some isolated test claims exist; the real end-to-end automatic loop and independent A/B benefit remain unverified.
- Developed a native Thoughtline Kernel package with review states and A/B/C perspective lenses. Host integration was not established.
- Refined World Engine / DOOR / ORBITAL / ECHOFOLD.VME into source-backed spatial representations with cached clips, dependency fingerprints, zoom into real contexts, and optional editable views.
- Refined VELA (music player / library / separate DAW workbench), GHOSTFIELD (DAW-independent virtual MIDI service), GREMLIN (offline mobile/desktop intake), PARALLAX (source-preserving browser boundary), UNDERBYTE and the phone-first TimePair design.
- Defined NAPALM as one experimental program/interface among many: locally modifiable models, tools and software environments, not the entire IXO product.

## What the evidence does and does not say
**HOST:** a specified workflow was observed or recorded on a specified host. Does not certify every program.
**STAGED:** an isolated unit or scenario run was reported. Does not prove live integration.
**PACKAGE:** source, runnable archive or implementation candidate exists; active machine acceptance not established.
**DESIGN:** contract or visual prototype is specified but cannot be described as shipping functionality.
**UNKNOWN:** source identity, host status, result or owner needs investigation.

Counts across those categories are **not additive** across different dates, branches, packages or test environments. The November 2 Windows test count and November 3 candidate bench are separate datasets.

## Present source-of-truth limitation
